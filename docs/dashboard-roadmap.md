# Новый дашборд: дорожная карта

Дата начала: 07.10.2026. Ветка: `codex/data-marts-realty`.

## Цель

Полноценный интерфейс React + TypeScript + Vite, API Python + FastAPI,
графики ECharts, карта MapLibre без Яндекса. Первая страница для согласования:
«Профиль застройщика». Визуал согласуется до подключения API и переноса других
страниц. Текущий Streamlit сохраняется как рабочий интерфейс для сравнения.

## Этапы и статус

22.10.2026, исправлена готовность ипотечной страницы: скрытые/пустые контейнеры
капчи не останавливают браузер или HTML-парсер. Вычисленная видимость передаётся
в копии DOM, сам документ не меняется. Загрузчик ожидается, таймаут загрузки
отличается от видимой капчи/отказа. Сохранены точные ответы и проверка периода.
Приватная диагностика JSON/PNG ограничена пятью парами, не содержит HTML,
заголовков, cookies и параметров URL, не публикуется. Утренний цикл проверяет
ипотеку до обязательных источников, чтобы сбой ЕРЗ не пропускал проверку;
условия безопасной публикации остальных данных не ослаблены.
Браузерные локальные фикстуры проходят, включая CSS-скрытые элементы и передачу
снимка парсеру. Живой запуск отдельного браузера показал настоящий отказ
«Доступ заблокирован», подтверждённый скриншотом, а не успешный сетевой сбор.
Доступ с Debian требует отдельной проверки; импорт архива не является решением
для ежедневной загрузки.

22.10.2026, ипотечное кредитование — полный помесячный сбор в подтверждённой
пользователем браузерной сессии: январь 2009 — август 2026, РФ и Москва,
424 наблюдения «регион–месяц», 1272 строки с сегментами.
Подготовлены React-страница `/economics/mortgage`, API `/api/v1/mortgage`,
годовые объём/количество, два месячных графика первички/вторички, три линии
месячной ставки и параметры кредита. Расчёты, пропуски и Excel проверены тестами;
визуальная проверка 320–1920 px поддерживает отдельный тестовый набор и
изолированную копию реальной истории без изменения рабочего raw-файла.
Подготовлены годовые checkpoints и дополнительная публикация без расширения
обязательных восьми источников существующего сайта. По предоставленному HTML
добавлен адаптер `pipeline.downloaders.nashdom_mortgage`: регион, год, месяц,
строго режим «за месяц», подтверждение завершения запросов и устойчивых карточек.
По уточнению пользователя режим «с начала года» не собирается: суммы для
накопленных/годовых графиков рассчитываются из помесячных наблюдений. Данные
сохраняют точные ответы запросов страницы `dashboard/general`/`dashboard/details`,
а не округлённые карточки; годовой итог не выдумывается из неполного года.
Docker `--mortgage` поддерживает продолжение и частичную публикацию. ДОМ.РФ
на машине разработки потребовал ручную проверку доступа, после которой реальная
история импортирована в рабочие данные. Сегменты источник предоставляет с 2016 года.
Для обоих регионов декабрь 2015 и октябрь 2016 имеют HTTP 500 только у параметров
кредита: эти поля остаются null, остальные измерения сохранены. Проверены точные
значения API и Excel; доступ из Docker на Debian отдельно не проверен.
Добавлен безопасный офлайн-импорт полного capture-файла, без переноса сессии и
с защитой от старой/неполной замены. Старый адаптер округлённых карточек мигрирует
на точные значения однократно; проверенные годы повторно не скачиваются без причины.

21.10.2026, согласовано правило для реконструируемых МКД без общей площади:
при заполненной жилой площади общая рассчитывается как `жилая / 0,58`,
МОП — как расчётная общая минус жилая. Правило применяется в месячной структуре
оперативного ввода, её месячном приросте и АППГ, в том числе к прошлому году.
Реконструкция определяется по столбцу K «Наименование объекта», например K4602.
Исключение: подтверждённое пользователем РВ `77-01-012565-2025`, Космодамианская
набережная; в его наименовании только «Жилой комплекс». На остальные МКД
без признака реконструкции коэффициент автоматически не распространяется.
Заполненные общие площади, ИЖС, нежильё и строки без жилой площади не заменяются.
Raw-файл, признаки исходного измерения и ранее согласованные графики не меняются.
В API `structure.areaEstimates` и Excel `Area estimates` сохраняются исходная
жилая площадь, коэффициент, расчётные общая/МОП, адрес и строка источника.

21.10.2026, уточнение оперативного ввода: выбор года месячной структуры ограничен
2023–2026, включая восстановление старых ссылок. История двух нижних графиков
и годовой ввод не ограничиваются. `≥` означает сумму заполненных площадей РВ,
а не новую категорию объектов; точный прирост и АППГ не рассчитываются, если
нужные площади в соответствующем периоде не заполнены. В проверенном файле
`monitoring_2_0_20261016.xlsx` пусты `Реестр РВ!W4602` (апрель 2026, Отрадная 4А)
и `W3598` (июнь 2025, Космодамианская набережная). Источник не исправлялся.
Линейные объекты: годовая история — «Данные с 2011 года» мониторинга, прогноз —
«Прогнозы», отдельный годовой план — сумма четырёх кварталов сохранённого ДСТИ.

21.10.2026, `linux-docker`: ввод разделён в навигации на оперативные данные,
годовой ввод и линейные объекты. Оперативная месячная структура идёт первой,
с отдельными приростом за месяц и сравнением к прошлому году; неполные измерения
явно отмечаются. Далее два графика с независимыми периодами и прогнозами РВ.
Годовой ввод подписывает фактический период 2026 года и ставит прогноз отдельным
столбцом справа. Линейные объекты: шесть плашек, шесть годовых графиков,
индивидуальные горизонты прогноза и сохранённый квартальный API. Все прогнозы —
из сохранённого листа «Прогнозы», без достройки отсутствующих значений.
Подпись серого ряда на оперативном вводе и РС: «Годовые значения».

20.10.2026, `linux-docker`: уточнены РС и ДОМ.РФ. РС использует согласованные
годовые итоги на всех графиках, учитывает МОП во «Всего» и сохраняет все 12
месяцев выбора с фактическим периодом текущего года. Структура показывает все
годы; нежильё объединено на одной шкале без выдуманных соответствий категорий.
ДОМ.РФ получил крупные KPI, площади внутри кругов и чистую месячную диаграмму.
Общее форматирование чисел не меняет точность выгрузок; годовые прогнозы
выделены пунктиром и штриховкой, исторические итоги остаются сплошными.
Дополнительно согласовано: разница годового итога нежилья с полной исходной
разбивкой относится со знаком в «Прочие»; исходные значения и корректировка
сохраняются в API и выгрузках, остальные категории не перераспределяются.
С 2022 года структура нежилья классифицируется по AR «ОСМ код», а не по ФНО:
02–09 — социальные, 10 — торговые, 14 — административно-деловые,
13 — промышленные, 11 — гостиницы, остальное — прочие. Разбивка до 2022 года сохранена.

## Принятые решения

- Строгий деловой интерфейс по предоставленному HTML-образцу; тёмная и светлая темы.
- Вложенная навигация: рынок недвижимости → текущее строительство / ввод / профиль → страницы.
- Открытые разделы меню сохраняются; фильтры профиля хранятся в URL.
- Основные графики используют ECharts; наведение работает на каждом сегменте столбца.
- «Жилое» и «МОП» имеют разные контрастные цвета.
- Длинные страницы прокручиваются вертикально; широкие таблицы — внутри области таблицы.
- Графики не имеют внутренних полос прокрутки и не обрезают подписи.
- API передаёт показатели, единицы, доступные фильтры, источники и версию снимка;
  оформление задаёт фронтенд.
- Перенос интерфейса не меняет базу данных. Существующий SQLite-пилот сохраняется;
  PostgreSQL/PostGIS, серверное размещение и авторизация — отдельные этапы.
- Источники обычных показателей сохраняются, включая лист 4 по действующим правилам.
  Только карта использует ОКС с датой выдачи с 2011 года и все РВ, без листа 4.

## Первый Визуальный Этап (История)

- Просмотр: `http://localhost:5173`; прежний Streamlit: `http://localhost:8501`.
- Повторный запуск: из `frontend` выполнить `pnpm install`, затем `pnpm dev`.
  На текущей машине pnpm доступен в bundled runtime; см. `frontend/README.md`.
- Фиксированный снимок: ПИК (Москва/РФ), САМОЛЕТ (Москва/РФ), CAPITAL GROUP (РФ).
  Регион выбирает только квартирографию. Прочие разделы явно указывают географию.
- Переключение тем и раскрытий меню сохраняется; компания, регион и годы — в URL.
- Графики поддерживают сегментные подсказки, переключение серий, CSV/PNG.
  Реестры содержат все строки выбранной компании, поиск, страницы и CSV.
- API, автоматическое обновление данных и Excel не подключены: это следующий этап
  после утверждения оформления. Другие пункты меню открывают старые страницы.

- Размеры экрана: 360, 390, 430, 768, 1280 и 1920 px; изменение размера окна.
- Меню, темы, фильтры, ссылки, подсказки, CSV/PNG, загрузка и ошибки.
- Экспорт Excel и автоматическое обновление через API проверяются на этапе API.
- Карта: масштабирование, заполнение области, фильтры и качество координат.

### Обновление На Другом Компьютере

Из корня репозитория, находясь в ветке `codex/data-marts-realty`:

```powershell
git pull --ff-only origin codex/data-marts-realty
.venv-dashboard\Scripts\python.exe -m pip install -r backend/requirements.txt
```

В каталоге `frontend` выполните `npm.cmd install`, затем перезапустите API и
`npm.cmd run dev`. Полные команды создания среды и запуска: `backend/README.md`.
Нужны полный репозиторий с данными, Python 3.12 и Node.js 24/npm. Сайт открывается
на `http://localhost:5173`, корень `/` остаётся профилем, главная доступна в меню.
Авторизации для публичного размещения ещё нет; TDM предназначен только для
доверенного localhost. Для production-карты нужен собственный или разрешённый
провайдер тайлов; публичный OSM по умолчанию используется только для локального
интерактивного просмотра. Координаты остаются предметом отдельной проверки.
