# Fedstat: экспорт возвращает HTML / 503

Лог `update_20260929_140352_218647_95007899.log` показывает успешное чтение дат паспорта, но вместо Excel сервер возвращает HTML или HTTP 503. Это не подтверждает получение новых данных.

Причина подтверждена по текущему `FGrid.prototype.downloadFile` на сайте: выбранные данные экспортируются через `/indicator/downloadData.do?format=excel`, с полем `title` и CSRF-полями из `#downloadTokenHolder`. Клиент использовал `/indicator/data.do?format=excel`, поле `indicator_title` и не передавал CSRF-поля. `data.do` в актуальном коде сайта обслуживает другие операции таблицы.

Исправлено в клиенте:

- Excel и SDMX используют актуальный `downloadData.do`; название передается в `title`. Перед каждой попыткой форма загружается заново, CSRF-поля читаются вместе с соответствующими cookies. Значения токенов не печатаются. Выбранные годы, регионы и виды индексов сохранены.
- HTML или ошибка browser fetch теперь передают управление обычному POST формы на fedstat.ru. Раньше преждевременный `return None` делал этот путь недоступным.
- Ответ fetch с ошибочным HTTP-статусом не сохраняется как успешная загрузка. Готовые файлы проверяются перед заменой предыдущего файла.
- При явной HTTP-ошибке в заголовке страницы после POST формы ожидание прекращается после короткого опроса, без полного 120-секундного ожидания файла.
- `--force` пропускает сравнение дат, но сохраняет даты предыдущих успешных загрузок и состояние невыбранных показателей. Неизвестные ID завершают запуск ошибкой до запуска браузера.
- `FEDSTAT_ONLY_IDS=31074` выбирает обе части ИПЦ.

Проверки без сети:

```powershell
python scripts/check_fedstat_transport.py
python scripts/check_fedstat_status.py
python scripts/check_fedstat_direct_fallback.py
```

Изолированная проверка актуальной части ИПЦ:

```powershell
python scripts/diagnose_fedstat_ipc.py --part 2
```

Она выполняет один цикл загрузки с транспортными fallback, ограничивает дочерний процесс 180 секундами и сохраняет лог, файл и квитанцию в отдельную папку `outputs/fedstat_ipc_*`. Производственные `state`, `downloads` и витрины не меняются; уведомления не отправляются. В логе указаны каталог проекта, Git HEAD, дата паспорта и, при успешном разборе, число наблюдений и последний период ИПЦ. Валидный Excel без распознаваемых наблюдений ИПЦ считается ошибкой. Git HEAD не отражает незакоммиченные изменения.

Обычный запуск только двух частей ИПЦ (изменяет рабочие загрузки и состояние):

```powershell
$env:FEDSTAT_ONLY_IDS = '31074'
try { .\update.bat fedstat --no-notify --retries 0 }
finally { Remove-Item Env:FEDSTAT_ONLY_IDS }
```

Сетевая проверка 29.09.2026 после исправления endpoint и CSRF (`outputs/fedstat_ipc_20260929_141641_829541/diagnostic.log`) успешно скачала актуальную часть ИПЦ через multipart POST: 36 352 байта, 368 распознанных наблюдений, последний период — август 2026. Дата паспорта — 19.09.2026. URL-encoded попытка перед этим вернула HTML; резервный multipart путь с новым токеном сработал. Диагностика завершилась кодом 0, производственные витрины не менялись.

Историческая часть ИПЦ также успешно скачана (`outputs/fedstat_ipc_20260929_141727_060344/diagnostic.log`): 34 304 байта, 384 наблюдения, последний период — декабрь 2018.

Оба проверенных Excel и их квитанции скопированы в `outputs/ipc_rebuild_verified_20260929/downloads`. Настоящий orchestrator выполнен с изолированным `PARSER_ROOT` и аргументами `--skip-download --only ipc --no-notify`: один успешный ETL, ошибок нет. Результат содержит 752 строки, два региона (Москва и Российская Федерация), данные по август 2026; пропусков в значениях нет. Для обоих исходных файлов подтверждены скачивания 29.09.2026 в 14:16 и 14:17 МСК. Производственные state и витрины не изменялись.

Более ранняя проверка только исправленного browser fallback (`outputs/fedstat_ipc_20260929_141200_910350/diagnostic.log`) всё ещё возвращала HTML/503. Одного восстановления fallback было недостаточно. Все 30 показателей этим результатом не проверены.
