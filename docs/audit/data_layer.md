# Общий слой чтения данных

28.09.2026. Реализован локальный слой, независимый от Streamlit. Это законченный
технический участок плана, но не миграция базы/API и не полная приёмка точности.

## Граница ответственности

`pipeline/data_access.py` содержит все прежние семейства загрузчиков: показатели,
производные CSV, зарплату/ИПЦ/нацсчета, квартирографию, мониторинг 2.0 и статический
лист, ERZRF TOP/cards, эскроу, распроданность, ввод и ЕМИСС (год/периоды). Чистые
функции обработки тоже находятся здесь. Модуль не импортирует Streamlit, не
пишет витрины/status/state и не обращается в сеть.

`app/data_access.py` сохраняет имена загрузчиков и формат ответа страниц; в нём
только явные импорты общих помощников, делегирование и Streamlit cache. Нет
`import *`, переноса глобальных переменных из UI в core или копии бизнес-логики.
Диагностика повреждённых Excel возвращается через `DataAccess.issues`, а facade
отображает её при первом и повторном вызове.

```python
from pathlib import Path
from pipeline.data_access import DataAccess, DataContext

# Контекст хранит независимые пути и режим, не изменяет окружение процесса.
access = DataAccess(DataContext(root=Path("/snapshot"), use_marts=False))
data = access.load_monitoring_2_0()

# Вход задан явно; готовая витрина обходится даже при require_marts=True.
traced = access.load_monitoring_2_0(
    source_path=Path("/snapshot/input.xlsx"), include_provenance=True,
)
```

`DataContext.from_environment()` использует `pipeline.paths` и `PARSER_ROOT`,
`PARSER_DOWNLOADS`, флаги использования/обязательности витрин. Явный `DataContext`
фиксирует режим: изменение окружения другого потребителя его не меняет.
`pipeline/build_realty_marts.py` создаёт `use_marts=False` контекст, не импортирует
UI и не меняет `PARSER_USE_REALTY_MARTS`. `app.audit` использует общий реестр
источников и учитывает `PARSER_ROOT`.

## Свежесть и память интерфейса

В обычном и строгом режиме проверяются callable-источники. Обычный режим при
устаревшей/ошибочной витрине возвращается к raw, строгий сообщает об ошибке.
Состав текущих источников, размер и доступный `mtime_ns` сопоставляются с manifest;
старые manifest без точных метаданных сохраняют проверку времени raw относительно
файла витрины. Новый builder записывает `mtime_ns`. Для ввода/ЕМИСС реестр и загрузчик
одинаково выбирают первый существующий `VVOD_PATHS`: неиспользуемый резервный
каталог не делает только что построенную витрину устаревшей.

Перед Streamlit cache вычисляется версия конкретного семейства: пути,
size/mtime_ns/ctime_ns/inode его входов, manifest и соответствующей витрины.
Поэтому новая публикация, изменение manifest, новый/изменённый raw или CSV/pickle
статистики видны без ожидания TTL. В ключ входят root, downloads и режим чтения.
Выдача кэша остаётся обычной выдачей Streamlit с копией значения.

Индекс читает только активные каталоги данного источника. Повторные вызовы
проверяют метаданные известных каталогов/файлов; неизменённые каталоги не обходятся
заново через scandir. Архивные каталоги исключены из live selection, глобального
`rglob` архивов на каждом вызове нет. Это метаданные файловой системы, а не
криптографический монитор изменений. Произвольное изменение содержимого с
сохранением всех доступных метаданных не является поддерживаемым протоколом
публикации. Атомарность согласованного набора нескольких pickle ещё не обеспечена.

## Происхождение мониторинга и дедупликация

`pipeline/source_records.py` определяет SHA-256 файла и идентичность строки:
SHA-256 компактного UTF-8 JSON `[file_sha256, source_sheet, source_row]`.
`source_row` — исходная строка Excel, начиная с 1; при `header=0` первая строка
данных имеет номер 2. Она фиксируется сразу после чтения, до фильтрации,
объединения листов и разложения строки на показатели.

При `include_provenance=True` wide-loader добавляет `source_sheet`, `source_row`,
`source_file_sha256`, `source_record_id` в RV/OKS. Обычные ответы сохраняют прежние
колонки. `pipeline/parsers/nashdom_monitoring_2_0.py` записывает те же поля в каждую
метрику исходной строки. SHA-256 повторно проверяется в конце разбора.

Processed-дедупликация мониторинга использует `source_record_id + metric_column`.
Разные корпуса/разрешения/компоненты с одним УИН или равными площадями сохраняются.
Повтор того же файла идемпотентен. Конфликт значения при той же идентичности
вызывает ошибку, вместо молчаливого `keep-last`. Legacy без provenance нельзя
надёжно дедуплицировать — такие строки сохраняются. В смешанном наборе они
не отключают проверку конфликтов и дедупликацию строк с доказанным ID. Ранее потерянные записи этим
не восстанавливаются автоматически: нужно отдельное контролируемое пересоздание
processed из проверенных raw. Рабочие processed/marts в этой задаче не изменялись.

Wide-loader и metric-parser пока сохраняют свои прежние предметные формы и
частично различающиеся преобразования (например, обработку старых годов).
Перенос из Streamlit не означает, что все различия этих представлений уже сверены.
Для SQL-пилота нельзя считать значения, превращённые прежней логикой в ноль,
доказанным исходным нулём; проверяемый адрес ячейки позволяет прочитать raw.

## Усиленный контракт ERZRF

Контракт `nakopl_vvod_quality` имеет версию 2. Допускается точная колонка площади
`Введено, м²` (также `м2`), непустые имена и полный набор конечных неотрицательных
чисел; ноль допустим, пропуск/«—»/нечисловое/отрицательное/inf отвергаются.
Реальная колонка качества `Введено МКД по ДДУ за 3 года` — количество домов,
и не проходит проверку площади. Неподходящая таблица даёт
`unavailable / invalid_commissioned_table`, без подстановки RF в MSK.

Регион пока подтверждается соглашением имени регионального collector-файла.
Оно не доказывает выбранную сортировку и накопительный период. Metadata явно
содержит `period_basis=collector_filename_only`, `observation_period=None` и
предупреждение. Безусловное «с 2016» не обосновано этими метаданными.
Проверка selected sorting/sidecar и неизвестного numeric TOP_TYPES mapping —
отдельный P0; цифры mapping не менялись наугад. Текущие локальные RF/MSK cumulative
Excel всё ещё содержат другую метрику и остаются недоступными.

## Проверки

- `check_data_access_core.py`: 10 temp integration tests — независимый импорт,
  raw-builder/неизменность env, два root, cache publication/manifest/raw/статистика,
  отсутствие повторного обхода архива, равенство public families/core, реальные
  позиции исходных строк. Тест builder отличает исходное raw-значение от старой витрины.
- `check_erzrf_region_scope.py`: 15 тестов, включая другой регион, legacy,
  точную метрику, пропуски/отрицательные значения и явный неизвестный период.
- `check_monitoring_provenance.py`: 7 тестов повторных/null УИН, равных строк,
  суммы компонентов, общего ID core/parser, идемпотентности и конфликта значения.
- Старые проверки strict/normal mart, monitoring parser, общих dedup keys и partial
  build прошли; добавленные core/ERZ/provenance проверки включены в общий validate.
- На отдельной копии 8 готовых наборов до/после переноса точно совпали 42 DataFrame
  и прежние данные payload. Ожидаемое изменение — ERZ quality metadata версии 2.
- Реальный сохранённый `monitoring_2_0_20260717.xlsx` прочитан без записи:
  **24 897 → 24 897** metric rows после dedup. Для УИН `HG8891-10-0002-001`,
  Лист4, строки Excel 1284–1296 сохранены **13 строк / 89 081,9 м²**; старый
  алгоритм оставлял 3 / 28 230,9 м². Это проверка конкретного дефекта, не всех данных.
- Независимое review воспроизвело два граничных дефекта (оба VVOD-каталога;
  смешанные legacy/modern строки) и подтвердило их исправления. Core10/provenance7
  повторно пройдены независимым запуском; общий validate до этих двух исправлений
  завершился успешно, после них выполнены целевые регрессии.

Сохранённый [baseline](baseline.csv) относится к состоянию до переноса core
и не перезаписывался. Benchmark snapshot включает новые pipeline-модули, а worker
явно получает пути временного снимка через `PARSER_ROOT/PARSER_DOWNLOADS/PARSER_STATE`.
Сравнение производительности до/после ещё не выполнено.

## Что этот участок не закрывает

Живые внешние источники и расписание, selected sorting ERZ, атомарная публикация
набора файлов, независимые эталоны всех показателей, полноценный браузер/телефон,
входящий TDM SDK/доступы и доставка бота, выбор/нагрузка/восстановление базы остаются
в [журнале плана](progress.md). Задание Gdebenz удалено, но удаление его файлов
было отклонено автоматической проверкой разрешений; считать файлы удалёнными нельзя.
