# API дашборда

API читает существующие витрины и исходные файлы через `pipeline.data_access`.
Расчёты профиля общие с контрольным снимком (`pipeline/profile_calculations.py`).
Не запускает загрузчики из интернета и ничего не записывает в raw/marts.

## Запуск на Windows

Из корня проекта сначала проверьте расположение файлов и установленный Python:

```powershell
Test-Path backend/requirements.txt
py --list
```

`Test-Path` должен вернуть `True`. Если `False`, перейдите в корень полного проекта;
на другой машине одного `frontend` недостаточно, нужен также каталог `backend`.
Если `py --list` не показывает Python 3.12 (или launcher `py` отсутствует), сначала
установите Python 3.12 с python.org, включая launcher, и заново откройте терминал.
Не запускайте команды по предполагаемым путям `.venv-dashboard` до создания среды.
Затем, с установленным Python 3.12:

```powershell
py -3.12 -m venv .venv-dashboard
.venv-dashboard\Scripts\python.exe -m pip install -r backend/requirements.txt
.venv-dashboard\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

Для фронтенда нужен Node.js 24 с npm. После установки заново откройте терминал
и проверьте `node --version` и `npm.cmd --version`. Ошибка «npm не является
командой» означает, что Node.js не установлен или его каталог ещё не доступен в PATH.

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Сайт: `http://localhost:5173`, документация API: `http://localhost:8000/docs`.
Vite проксирует `/api` в API. Оба терминала должны оставаться открытыми.
Используйте другой свободный порт API и переменную `DASHBOARD_API_TARGET` для Vite,
если 8000 занят. API по умолчанию доступен только на самой машине, без авторизации;
не выставляйте его в интернет напрямую.

На другой машине нужен весь набор файлов данных, не только папка `frontend`.
`PARSER_ROOT`, `PARSER_DOWNLOADS`, `PARSER_USE_REALTY_MARTS`,
`PARSER_REQUIRE_REALTY_MARTS` управляют существующим загрузчиком.
Витрины `.pkl` считаются доверенными локальными входами, не загружайте чужие pickle.
Отсутствующий мониторинг даёт HTTP 503, старый demo JSON не подставляется.

## Контракт

- `GET /api/v1/health`: готовность процесса (не подтверждение доступности данных).
- `GET /api/v1/catalog`: все компании мониторинга, регионы квартирографии, даты и версия.
- `GET /api/v1/profile?developer=пик&region=msk`: полный профиль по существующим правилам.
- `GET /api/v1/profile/export?developer=пик&region=msk`: Excel полного профиля и реестров.
  React передаёт `required_version` показанного профиля; изменение данных даёт 409
  вместо скачивания незаметно отличающегося отчёта.

Неизвестная компания/недоступный регион: 404; неверные параметры: 422;
ошибка исходных данных: 503. Неизвестные показатели сохраняются как null.
Ошибки загрузчиков не маскируются под отсутствие наблюдений: генерация не публикуется.
Версия отслеживает файловые сигнатуры; проверка выполняется при запросах не чаще
раза в 5 секунд. Новый согласованный набор публикуется атомарно; это не планировщик ETL.
Реестры профиля не ограничиваются правилами карты. Лист 4 сохраняется в обычных
показателях согласно прежним загрузчикам. Отдельный API карты описан ниже.

## API квартирографии

- `GET /api/v1/apartments/catalog`: `schemaVersion: 1`, `version`, `generatedAt`,
  `reportDate`, `source: {date, files, issues}`, `regions: [{id, label}]`,
  `developersByRegion: {msk: [{id, name, place}], rf: [...]}`.
- `GET /api/v1/apartments?region=msk`: те же метаданные, `region`, `apartments`
  (`type`, `count` в штуках, `areaThousandM2`), `distribution` (`range`, `sharePercent`),
  все строки `developers` и `regions`, `developerCount`, `regionCount`.
  Строка таблицы: `id`, `name`, `apartmentThousandCount`, `areaThousandM2`,
  `rooms: [{type, sharePercent}]`; `place` есть у девелоперов.
- `GET /api/v1/apartments/developer?region=msk&developer=<точное имя>`:
  метаданные, `region`, `developer` (строка таблицы), `summary`, `referenceAverages`,
  `rooms`, `comparison` (top-10 и выбранный девелопер, если он вне top-10).
  `summary`: `countThousand`, `areaThousandM2`, `averageAreaM2`, `marketSharePercent`,
  `marketBaseAreaThousandM2`, `place`, `totalDevelopers`.
  `referenceAverages`: `[{region, averageAreaM2}]`, в порядке Москва, РФ.
- `GET /api/v1/apartments/export?region=msk`: XLSX всех таблиц обзора без top-50.
  С `developer=<точное имя>` выгружается карточка, KPI, комнатность и сравнение.
  Необязательный `required_version` сверяется с версией поколения; при конфликте
  HTTP 409 и `X-Data-Version` текущего поколения. Успешный XLSX тоже имеет этот заголовок.

Без `region` выбирается первый доступный регион: Москва, затем РФ, как в legacy UI.
`id` девелопера равен исходному имени без нормализации; передавайте его URL-кодированным.
Сортировка по площади повторяет pandas-сортировку прежних страниц, включая равные
площади и пропуски. В таблице регионов Москва первая для обоих регионов; для Москвы
сначала добавляется московская строка РФ, затем убираются точные дубли имён.
Комнатность передаёт исходные проценты, не нормализованные ширины HTML-полос.
Типы комнат: `1 комн`, `2 комн`, `3 комн`, `4+ комн`; пропуски остаются null.

Средняя площадь девелопера: `(площадь * 1000) / (квартиры * 1000)`.
Доля рынка: площадь девелопера / **сумма площадей девелоперов выбранного региона**,
не площадь строки «Все квартиры». Средние по всем квартирам используют штуки
и `площадь * 1000`; показываются при том же условии доступности среднего KPI,
что и на странице 5. Нефинитные результаты (в том числе деление на нулевую базу)
становятся null, а не вымышленным нулём.

Сервис читает только `DataAccess.load_kvartirografia`, независимо от мониторинга
профиля. Файловая сигнатура проверяется раз в 5 секунд при запросах; загрузка
публикуется только при совпадении сигнатур до/после, без записи raw/marts.
Фатальная диагностика, отсутствие всех квартир/девелоперов и некорректная схема
дают 503; неизвестное имя/недоступный регион дают 404, неверные параметры 422.
Каталог сохраняет частичные данные. Обзор требует только основную таблицу квартир,
карточка — только таблицу девелоперов; отсутствие их основной таблицы даёт 503.
Другие пустые секции остаются пустыми. При отсутствии общих квартир карточка
девелопера остаётся доступной без `referenceAverages`. Каталог убирает точные
повторы id, сохраняя первое имя/место в порядке рейтинга; обзор содержит все строки.
Карточка берёт первое совпадение имени, а сравнение добавляет все совпадения вне top-10.
`source.files` — относительные пути **кандидатов** реестра DataAccess, не точный
список участвовавших файлов. `source.date` повторяет доступную дату manifest/raw
из загрузчика; она не доказывает выбор файла при fallback. Фактическая дата
отчёта отдельно находится в `reportDate`; диагностика — пары `[level, message]`.
Правила выбора валидного mart/raw и fallback не меняются; ошибки, которые сам
загрузчик скрывает при fallback, сервис дополнительно не реконструирует.

Проверка квартирографии, включая реальные источники и независимые legacy DataFrame:
`python -m unittest discover -s backend/tests -p test_apartments.py -v`.

## API распроданности и стройготовности

- `GET /api/v1/sales/catalog`: `{schemaVersion: 1, version, generatedAt,
  source: {date, files, issues}, regions: [{id, label, periods: [{id, label}]}]}`.
  Регион: `msk` / `rf`; период: `YYYY-MM`, подпись: `Январь 2020`.
  Каталог только загружает и проверяет данные/доступные периоды, не рассчитывает срезы.
- `GET /api/v1/sales?region=msk&period=2026-05`: те же метаданные,
  `region: {id, label}`, `period: {id, label}`,
  `metrics: [{id, label, unit, value: number | null, digits}]`,
  `charts: [{id, title, kind: 'bar' | 'line', unit,
  series: [{id, name, unit, points: [{x: string, y: number | null}]}]}]`,
  `tables: [{id, title, columns: [{id, label}],
  rows: Record<string, string | number | null>[]}]`.
- `GET /api/v1/sales/export?region=msk&period=2026-05&required_version=<version>`:
  XLSX выбранного среза целиком: четыре KPI, все точки прогноза и месячных графиков,
  все строки шести таблиц, оригинальные ID/подписи колонок, источники и версия.
  `required_version` обязателен (без него 422); конфликт — 409 с `X-Data-Version`.
  Успешный экспорт тоже содержит `X-Data-Version`. Excel не повторно читает источники:
  весь файл строится из одного скопированного payload согласованного поколения.

KPI ID в порядке legacy: `volume`, `sold`, `ready`, `ratio`. Единицы: `тыс. м²`,
`%`, `%`, `%`; `digits: 0`. Значения не округляются в API. Строка KPI выбирается
первым совпадением `str.contains` как на странице 6, без пересчёта отношения Р/С.
Отсутствующий KPI и нефинитное числовое значение — null, не ноль.

Графики: `forecast` (`bar`), `monthly_volume` (`line`), `monthly_percent` (`line`).
Прогноз сохраняет **общую legacy-ось**, без разделения на две оси и без изменения
масштаба: у графика `unit: ""`, единица каждой серии — `series.unit` (`тыс. м²`
для объёма, `%` для остальных KPI). На фронтенде единицы необходимо раскрывать
для каждой серии. Исходная колонка KPI `единица` иногда содержит объём проданного
жилья, поэтому она не является единицей прогнозной серии. ID прогноза:
`forecast_0`, `forecast_1`, ... в исходном порядке строк; имена не нормализуются.
`x` прогноза — исходная подпись колонки без `прогноз_`, включая `2031+`,
в порядке колонок DataFrame, **не в сортировке по году**. Null-точки не удаляются.
Месячный `x` — `YYYY-MM`, сортировка по `period` повторяет pandas legacy.
Месячные графики показывают всю доступную историю региона, не только выбранный месяц.
Если объём отсутствует за всю историю, `monthly_volume` отсутствует, как в legacy.
Процентные серии: `sold`, `ready`, `ratio`, только имеющиеся в истории.

Шесть таблиц всегда присутствуют: `fed_okruga`, `regions`, `developers`,
`by_dev_volume`, `by_population`, `by_class`. Их `columns.id` — исходные имена,
не подписи после rename. `columns.label` точно повторяет legacy, включая
`Объём, м²`, `Распроданность`, `Стройготовность`, `Отношение Р / С` и
legacy-обрезание подписи первого столбца. Строковые поля, пробелы, NBSP, `%` и
`—` сохраняются без числового парсинга; `_num` и служебные колонки не выводятся.
Пустые секции/срезы имеют `rows: []`; отсутствующий/пустой исходный лист также
имеет `columns: []`. Урезания строк, top-N и правил карты нет. Экспорт защищает
текстовые ячейки и заголовки от Excel formula injection; null остаётся пустой ячейкой.

Без фильтров выбирается Москва, затем РФ, и последний период выбранного региона.
Периоды региона берутся из `DataAccess.load_rasprodannost`, не из глобального списка.
Неизвестный регион/период, включая недоступный месяц другого региона: 404;
пустой параметр: 422; фатальная диагностика, отсутствие KPI, неправильная схема:
503. Предупреждения источников передаются в `source.issues`.

Sales использует общий `DataContext` и те же исключения, что apartments.
Сигнатуры контекста/файлов проверяются раз в 5 секунд при запросах, до и после
загрузки. Поколение публикуется атомарно; каталог и рассчитанные срезы возвращаются
через deepcopy; кэш срезов ограничен 32 сочетаниями регион/период.
Источник только `DataAccess.load_rasprodannost`; исходная страница и правила
mart/raw/fallback не изменены, ETL/записей raw/marts нет. `source.files` — кандидаты
DataAccess, **не доказанный список использованных файлов**; `source.date` —
дата свежего raw-кандидата (manifest используется только при отсутствии raw-даты),
не подтверждение выбранного файла при fallback; основание указано в `dateEvidence`.
Выбранный отчётный месяц явно находится в `period`. Скрытые самим загрузчиком
ошибки fallback дополнительно не реконструируются.

Проверки: `python -X utf8 -m unittest backend.tests.test_sales -v`.
Тесты исполняют неизменённую страницу `app/pages/6_Распроданность.py` с подставленным
UI: оба региона, несколько реальных периодов, все KPI, прогнозные и месячные точки,
шесть полных таблиц и подписи. Отдельно проверяются raw-режим, входные SHA-256,
кэш/deepcopy, 404/503/409, полный XLSX и защита формул. Это сравнение данных и
расчётов текущего UI, не визуальная браузерная проверка и не подтверждение
достоверности исходных значений.

## Оперативный ввод: месяцы и структура

`GET /api/v1/commissioning/operational/catalog` предлагает все месяцы 1–12
для сравнения исторических периодов. `defaultMonth` по-прежнему выбирается
по месяцам текущего года в РВ и дате исходного файла. Год и квартал структуры
независимы от месячного фильтра исторических таблиц.

Выбор декабря не означает, что текущий год закрыт: суммируются только имеющиеся
строки РВ до выбранного месяца, без прогноза отсутствующих месяцев. Историческое
жильё — сумма загруженных месячных значений листа «Данные с 2011 года»; нет проверки
полноты всех месяцев выбранного периода. При отсутствии истории период остаётся
`null`, а годовые значения не подставляются вместо него. Исторические периодные
значения нежилья рассчитываются только с 2022 года по РВ; раньше остаётся `null`.
Это прежние правила расчёта; расширение селектора не добавляет наблюдений.

Отчёт дополнительно содержит `treeGrowth: {<ключ tree>: number | null}` для всех
15 показателей: `(текущий / прошлогодний - 1) * 100`, без округления, за тот же
квартал либо период с начала года. Если предыдущего года нет в РВ или знаменатель
нулевой, значение `null`. Значения `tree` и `treeRows` не меняются.

Проверка: `python -X utf8 -m unittest backend.tests.test_operational -v`.

## API экономики

Три независимых семейства: `salary`, `ipc`, `accounts`. Каждый использует только
соответствующий `DataAccess.load_salary`, `load_ipc`, `load_national_accounts`.
API не импортирует Streamlit, не запускает ETL, не меняет processed/raw/marts и
не применяет ограничения карты. Расчёты: `pipeline/economics_calculations.py`.

Карта и сервисные разделы описаны ниже отдельно; ограничения карты не относятся
к экономическим и другим аналитическим отчётам.

- `GET /api/v1/economics/{family}/catalog`: стандартные `schemaVersion: 1`,
  `version`, `generatedAt`, `source`, а также `family`, `controls`, `defaults`, `years`.
  `controls` описывает каждый control, тип, варианты, значения по умолчанию;
  `periods` указывает режимы его видимости. `years` информационный: legacy показывает
  всю историю, отдельного фильтра лет нет.
- `GET /api/v1/economics/{family}/report`: те же метаданные, `selection`, `charts`,
  `tables`. Корень `/api/v1/economics/{family}` является алиасом отчёта.
- `GET /api/v1/economics/{family}/export?required_version=<version>`: полный XLSX
  выбранного отчёта. Все фильтры отчёта передаются также в экспорт.
  Без `required_version` 422; конфликт 409 с `X-Data-Version`; успешный ответ
  содержит этот же заголовок. Файл строится из одного скопированного payload,
  без повторного чтения источников. Версия относится к источникам, не к фильтрам:
  потребитель обязан передать показанные фильтры вместе с показанной версией.

Списки передаются повторяющимися параметрами, не CSV:
`regions=Москва&regions=Российская%20Федерация`, `months=1&months=12`.
ID региона/отрасли равен точной legacy-строке, без нормализации.
Отсутствующий список выбирает default; единственный пустой параметр (`views=`,
`months=`, `quarters=`, `structure_industries=`) означает пустой мультиселект.
Смешивание пустого значения с другими недопустимо. Неизвестные варианты/числа
дают 404; неверный тип/enum, CSV в числовом списке и пустой одиночный регион 422.
Пустой допустимый выбор или отсутствие наблюдений даёт пустые charts/tables,
не вымышленные значения и не source fallback. Ошибки источника/схемы дают 503.

**Salary**: `period=year|quarter|month` (default `month`), `region`, повторяемый
`views` (`Строительство`, `Всего`, default оба), `ytd=false|true`, `months`, `quarters`.
Регион по умолчанию первый legacy `moscow_first`; кварталы по умолчанию все
доступные выбранному региону/отраслям/режиму. Каталог содержит `regions`,
`quarterOptionsByRegionMode: {<регион>: {direct: number[], ytd: number[]}}`.
Год: декабрьский YTD плюс отдельные годовые строки 2011–2012. Квартал direct:
среднее месячных значений, округлённое до двух знаков; YTD: последний месяц квартала.
Месяц: direct или YTD загрузчика, включая его правило достройки января.
Единица графика `руб.`; колонка выгрузки `значение_руб`.

**IPC**: `period`, повторяемый `regions` (default первый регион), `months`, `quarters`,
`index_base=month_to_month|ytd_to_yago` (default `month_to_month`).
Квартал берёт последний месяц квартала выбранного индекса, не среднее/произведение.
Год всегда декабрьский `ytd_to_yago`, независимо от скрытого index_base.
Единица `%`; колонка выгрузки `ипц_%`.

**Accounts**: история с 2011 года, шесть блоков с независимыми controls:
`block1_regions`, `block2_regions`, `block3_regions`, `block4_regions` (повторяемые,
default Москва); `structure_region` (Москва), `structure_mode=value|share` (value),
`structure_industries`; `index_region` (Москва), `index_industries`, `show_total=true`.
Регионы блоков Москва/Российская Федерация доступны независимо от наличия наблюдений.
Каталог содержит `blocks`, `minimumYear`,
`structureIndustries: {<регион>: {value: [{id,label}], share: [...]}}`,
`indexIndustries: {<регион>: [{id,label}]}`. Default отраслей вычисляется для текущего
региона/режима: Строительство, иначе первая доступная. Структура предлагает отрасли
2016+, если они есть; старые ОКВЭД продолжают участвовать в сумме/«Остальных».
Фронтенд сохраняет выбранные отрасли между сменами controls, пересогласуя их с каталогом.
Невалидные явные отрасли API отклоняет 404, молча не заменяет.

Блоки 1–4 имеют единицы `трлн руб`, `млн руб/чел`, `%`, `%` соответственно.
Масштабы ВРП/ВВП: `1e-6`/`1e-3`; на душу оба `1e-6`. В структуре value масштаб
зависит от **первой строки**: `млн руб` → `1e-6`, иначе `1e-3`; итог `трлн руб`.
Share и индекс имеют `%`. Эти правила намеренно не заменены пересчётом каждой строки.
Структура суммирует все отрасли, кроме «Всего», вычитает выбранные из остатка,
ограничивает остаток снизу нулём. `show_total` блока 6 меняет только линию:
legacy-пивот и выгрузка всегда включают доступное «Всего» даже при `false`.

График: `{id,title,kind:'bar'|'line',stack:boolean,unit,
series:[{id,name,unit,points:[{x:number|string,y:number|null}]}],
columns:[{id,label}],rows:Record[]}`. `columns/rows` точно повторяют legacy download,
а не реконструируются из точек. ID: `salary_year|quarter|month`, `ipc_year|quarter|month`,
`na_block1`–`na_block6`. `tables` с ID `<chartId>_pivot` повторяют показанные pivots
(`aggfunc='first'`, порядок, null). У блока 5 также `totals:[{x,y}]`; series включает
«Остальные отрасли», pivot включает остаток и «Всего», legacy rows только выбранные
отрасли. Это различие сохраняется в XLSX: отдельные полные листы series, rows, pivots,
totals, справочник колонок/единиц, controls, версия и provenance. Строки/заголовки
явно записываются текстом для защиты от Excel formula injection. Пропуски/нефинитные
числа API передаёт как null, XLSX как пустые ячейки; legacy groupby sum/mean сохраняются.
Дубликаты не убираются дополнительно: серии и rows сохраняют их, pivots берут first.
Подписи месяцев/кварталов используют текущие `month_label`/`quarter_label`.

Сигнатуры контекста и файлов `DataAccess.data_version` проверяются раз в 5 секунд
при запросах; публикация только при совпадении до/после загрузки и чтения provenance.
Кандидаты включают processed и все CSV derived, которые читает текущий загрузчик,
в том числе прочитанные, но затем отфильтрованные строки. Изменения локальных
row-recorded исходников/receipts также обновляют metadata/version без запуска ETL.
Catalog/report возвращаются через deepcopy; ошибочные поколения не публикуются,
старое поколение после обнаруженной ошибки не подставляется. API ничего не опрашивает
в фоне, до следующего окна проверки отдаётся согласованное прежнее поколение.

`source.files` имеет `fileEvidence: 'candidates'` и не утверждает фактическое участие.
`recordedSources` — значения `source_file` в загруженных строках; их основание отдельно
указано в `recordedSourceEvidence`, это не доказательство соответствия нынешних raw.
`provenance:{columns,rows}` и `downloadSummary` используют `pipeline.download_provenance`,
как legacy; там отдельно дата файла, подтверждённая receipt дата скачивания, период,
не найденные файлы и необходимость ETL. `source.date` — последняя известная дата
изменения row-recorded файла (МСК), null если неизвестна; `dateEvidence` прямо указывает,
что это не дата скачивания. Ручные/расчётные подписи не превращаются в найденные файлы.

Проверки: `python -X utf8 -m unittest backend.tests.test_economics -v`.
Набор выполняет неизменённые три страницы через AST с UI-capture и сопоставляет
series, полные download rows и pivots, включая оба региона, все периоды/index/YTD,
независимые accounts controls, пустые выборы, конфликтующие дубликаты источников,
null и масштабы. Отдельно проверяет сигнатуры/хэши, публикацию, кэш/deepcopy,
404/422/503/409, обязательную версию XLSX, полный экспорт/единицы и literal cells.
Это сверка данных текущего UI, не визуальная браузерная проверка и не сертификация
исходных значений. Совместный API-процесс перезапускает только основной чат.

## Карта И Сервис

- `/api/v1/map/catalog`, `/api/v1/map`, `/api/v1/map/export`: карта читает только
  два именованных листа самого свежего monitoring-файла. ОКС ограничен фактической
  датой `Срок выдачи РС >= 01.01.2011`; неизвестные даты не подменяются годом ввода.
  РВ читается целиком, без ограничения года и без объединения с Лист4. Общие
  загрузчики и отчёты не меняются. Статус «Строится» берётся из ОКС, введённые — РВ.
  Сохраняются существующие объединения строк по УИН и правила координат.
- Фильтры: `developer`, повторяемые `status`/`okrug`, `year_from`/`year_to`,
  `quality=all|located|approximate|missing`, `only_with_coords`. Неизвестный год
  сохраняется в диапазоне лет. `located` не означает проверенные точные координаты:
  это геометрия/локальный кэш; центры районов/округов имеют `approximate`.
  Ответ включает все filtered rows, GeoJSON, общие/фильтрованные счётчики, scope
  и предупреждения. XLSX требует показанную `required_version`, конфликт — 409.
  Версия учитывает workbook и `data/derived/monitoring_geocodes.csv`; API не
  запускает геокодирование и не записывает эти файлы. Пустой адрес не сопоставляется
  с пустым адресом кэша; ведущие нули cache object_id сохраняются.
- `/api/v1/updates`: read-only журнал, статус realty, свежесть mart по текущим
  кандидатам raw, история мониторинга, все показатели и Telegram preview.
  `days` и `monitoring_days`: 7/30/90; `only_errors` фильтрует только события.
  Нет кнопок запуска ETL и никаких автоматических отправок.
- `/api/v1/tdm/catalog`: состояние подключения (только boolean, без bot token),
  выбранные dashboard datasets, исходные файлы и процессный `actionToken`.
  POST `/groups`, `/send`, `/upload` требуют `X-TDM-Token`; отправки дополнительно
  требуют `Idempotency-Key`. Повтор одного ключа возвращает прежний результат,
  неоднозначная ошибка не вызывает автоматическую повторную отправку.
  `/send`: JSON `{kind: text|file|dataset,key,text,group}`. `/upload`: binary body
  и query `filename/caption/group`, максимум 50 MiB, временный файл удаляется.
  File/dataset выбираются из серверного разрешённого списка, не произвольного пути.
  Конфигурация прежняя: `TDM_BOT_TOKEN`, `TDM_WORKSPACE_ID`, `TDM_GROUP_ID`,
  `TDM_DISABLED`. Сам API TDM намеренно принимает только localhost-клиента;
  публикация в сеть требует отдельной авторизации, не просто `--host 0.0.0.0`.

Проверки: `python -m unittest backend.tests.test_map backend.tests.test_updates
backend.tests.test_tdm -v`. Все отправки в тестах подменены mock, реальные сообщения
и файлы не отправляются. Для карты проверены date boundary, отсутствие Лист4,
неизвестный год РВ, cache priority/IDs, read-only входы и version-pinned Excel.

Для полного набора тестов установите `backend/requirements-dev.txt`: Plotly и Jinja2
нужны для изолированного исполнения прежних графиков/Styler в сверках. Сам новый API
работает без Streamlit/Plotly. `pyarrow` включён в runtime requirements, поскольку
сохранённые pandas-витрины могут содержать Arrow-массивы; без него такие pickle
не читаются. `requests` нужен существующему TDM-клиенту и notifier.
