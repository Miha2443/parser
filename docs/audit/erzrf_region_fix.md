# ERZRF: устранение неподтверждённого регионального накопленного ввода

Проверено 28.09.2026 на локальных файлах. Источники не скачивались и не изменялись; действующая витрина не перезаписывалась.

## Что подтверждено до исправления

В `data/marts/realty/erzrf_top.pkl` находились:

|---|---:|---|

| `msk` | 100 | Полное совпадение с фильтром `rf` по подстроке «Москва» в `Наименование, регион` |

Для ПИК оба среза содержали 2 675 176 м² и `Регионов = 9`. География регистрации/названия компании не задаёт географию всего этого объёма. Поэтому ни фильтрация по названию, ни копирование общей таблицы не подтверждают московский срез. Имя `TOP_EXCEL` также не подтверждает российский охват и накопленный период.

Отдельные файлы `top_nakopl_vvod_{rf,msk}_20260702.xlsx` существуют (307 и 106 строк соответственно), но в них нет колонки «Введено». Есть «Средняя оценка», «Строится, м²» и показатели качества ЖК. Аналогичная проблема есть в файлах от 18.06.2026. Наличие слова `nakopl` в имени не делает эти таблицы данными накопленного ввода.

## Поведение после исправления

- `TOP_EXCEL` не используется для заполнения ни РФ, ни Москвы.
- Принимаются только отдельные файлы `top_nakopl_vvod_<region>_<YYYYMMDD>.xlsx` с колонками наименования и введённой площади. Географическое основание явно записано как контракт имени файла сборщика (`scope_basis = collector_filename`); география имени застройщика не анализируется.
- Выбирается последний файл по `mtime`. Если он повреждён или имеет другую структуру, более старый файл не подставляется молча.
- `nakopl_vvod_quality` содержит `schema_version = 1`, а для каждого региона — `status`, `source_scope`, `source_kind`, `scope_basis`, `source`, `reason`.
- Старые витрины без этой версии метаданных не сохраняют свои формально подходящие таблицы накопленного ввода: каждый срез восстанавливается только из отдельного регионального файла. Это работает и при `PARSER_REQUIRE_REALTY_MARTS=1`.
- Недоступный срез представлен пустым DataFrame, а не нулями или национальными значениями. Причины: `missing_regional_export`, `unreadable_regional_export`, `invalid_commissioned_table`.
- Версионная витрина повторно не читает raw при валидных метаданных. Для старой витрины проверка ограничена последним файлом каждого из двух регионов и выполняется в кэшируемом загрузчике Streamlit (`ttl=300`).

На проверенном локальном наборе после загрузки: `rf=0` строк, `msk=0` строк; оба статуса — `unavailable`, причина — `invalid_commissioned_table`. Это выявленный пробел источников, а не восстановленные данные. Страница профиля показывает предупреждение рядом с рейтингом.

Проверка качества больше не закрепляет произвольное условие «ПИК должен быть первым в обоих регионах». Она проверяет происхождение и согласованность статуса с данными, печатает предупреждения по отсутствующим срезам и завершает выводом `realty data integrity checks: ok; UNAVAILABLE: nakopl_vvod/rf, nakopl_vvod/msk`. Код 0 означает соблюдение проверенных инвариантов, а не полноту источников.

## Ограничения и следующий этап

Изменение не исправляет выгрузку другого рейтинга, ошибочно названную накопленным вводом. Нужны подтверждённые отдельные выгрузки; внешние источники в этой задаче не открывались. Контракт имени файла — существующий интерфейс сборщика; он не заменяет проверку выбранных фильтров на стороне сборщика.

Действующая старая витрина оставлена на диске для воспроизводимости; безопасное чтение обеспечивает загрузчик. Прямое чтение этого pickle в обход загрузчика всё ещё вернёт старое содержимое. После общего изменения pipeline следует штатно пересобрать витрину, чтобы сохранить версионные метаданные и актуальные строки/доступность в manifest.

Для отделения ETL от Streamlit региональную загрузку, проверку метрики и миграцию версии следует перенести в общий слой, сохранив thin-wrapper с кэшем. Сейчас `pipeline.build_realty_marts` вызывает `app.data_access`, а manifest отражает строки/файлы, но не проверяет данный семантический контракт. Общая проверка свежести в обычном режиме также пока не является частью этого исправления. Следующий контракт источников должен включать период, размер/mtime/хеш и подтверждение выбранного региона/сортировки сборщиком.

В старом manifest `TOP_EXCEL` встречается дважды среди источников ERZRF. На Windows шаблоны `top_*.xlsx` и `TOP_EXCEL*.xlsx` могут захватывать один файл; дедупликация списка источников относится к общему слою выбора файлов.
