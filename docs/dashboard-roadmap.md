# Новый дашборд: дорожная карта

Дата начала: 07.10.2026. Ветка: `codex/data-marts-realty`.

## Цель

Полноценный интерфейс React + TypeScript + Vite, API Python + FastAPI,
графики ECharts, карта MapLibre без Яндекса. Первая страница для согласования:
«Профиль застройщика». Визуал согласуется до подключения API и переноса других
страниц. Текущий Streamlit сохраняется как рабочий интерфейс для сравнения.

## Принятые решения

- Строгий деловой интерфейс по предоставленному HTML-образцу; тёмная и светлая темы.
- Вложенная навигация: рынок недвижимости → текущее строительство / ввод / профиль → страницы.
- Открытые разделы меню сохраняются; фильтры профиля хранятся в URL.
- Основные графики используют ECharts; наведение работает на каждом сегменте столбца.
- «Жилое» и «МОП» имеют разные контрастные цвета.
- Длинные страницы прокручиваются вертикально; широкие таблицы — внутри области таблицы.
- Графики не имеют внутренних полос прокрутки и не обрезают подписи.
- API передаёт показатели, единицы, доступные фильтры, источники и версию снимка;
  оформление задаёт фронтенд.
- Перенос интерфейса не меняет базу данных. Существующий SQLite-пилот сохраняется;
  PostgreSQL/PostGIS, серверное размещение и авторизация — отдельные этапы.
- Источники обычных показателей сохраняются, включая лист 4 по действующим правилам.
  Только карта использует ОКС с датой выдачи с 2011 года и все РВ, без листа 4.

## Агенты

| Роль | Модель | Рассуждение | Граница ответственности |
|---|---|---|---|
| Архитектор | `gpt-6-astra` | `high` | Архитектура и интеграция; основной чат |
| Дизайнер | `gpt-6.1-sol` | `high` | Визуальная система, навигация и адаптивность |
| Фронтенд | `gpt-6.1-sol` | `high` | React, таблицы, фильтры, ECharts |
| Бэкенд / данные | `gpt-6.1-sol` | `high` | Контрольный срез, расчёты, FastAPI и экспорт |
| Независимая проверка | `gpt-6-astra` | `high` | Ошибки, источники, регрессии и приёмочные сценарии |
| Документация | `gpt-6-luna` | `medium` | Отчёты по проверенным результатам |

Одновременно не более двух подагентов. Каждый получает конкретную задачу и
непересекающийся набор файлов. Роли не означают, что все агенты запущены постоянно.
Замена недоступной модели предварительно сообщается пользователю. Заключение агента
не заменяет сверку и браузерные проверки.

## Готовый визуальный этап

- Просмотр: `http://localhost:5173`; прежний Streamlit: `http://localhost:8501`.
- Повторный запуск: из `frontend` выполнить `pnpm install`, затем `pnpm dev`.
  На текущей машине pnpm доступен в bundled runtime; см. `frontend/README.md`.
- Фиксированный снимок: ПИК (Москва/РФ), САМОЛЕТ (Москва/РФ), CAPITAL GROUP (РФ).
  Регион выбирает только квартирографию. Прочие разделы явно указывают географию.
- Переключение тем и раскрытий меню сохраняется; компания, регион и годы — в URL.
- Графики поддерживают сегментные подсказки, переключение серий, CSV/PNG.
  Реестры содержат все строки выбранной компании, поиск, страницы и CSV.
- API, автоматическое обновление данных и Excel не подключены: это следующий этап
  после утверждения оформления. Другие пункты меню открывают старые страницы.

## Проверки

- Контрольные значения и серии сверяются на одном снимке, без изменения raw/marts.
- Пустые и недоступные данные не заменяются вымышленными значениями.
- Размеры экрана: 360, 390, 430, 768, 1280 и 1920 px; изменение размера окна.
- Меню, темы, фильтры, ссылки, подсказки, CSV/PNG, загрузка и ошибки.
- Экспорт Excel и автоматическое обновление через API проверяются на этапе API.
- Карта: масштабирование, заполнение области, фильтры и качество координат.

## Порядок переноса после профиля

Квартирография → квартирография по девелоперу → распроданность → годовой ввод →
оперативный ввод → линейные объекты → текущее строительство → зарплата → ИПЦ →
ВРП/ВВП → карта → главная и сервис.
