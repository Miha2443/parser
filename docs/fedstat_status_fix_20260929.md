# Fedstat: достоверный статус обновления

## Подтверждённая ошибка

В `_to_delete/update_20260720_150259.log:253–258` полный запуск сообщает
«скачано файлов — 0», «проверено индикаторов — 29/30», пропуск без даты и
затем «fedstat: успех». Выше в том же логе есть ошибка скачивания новой версии:
вместо Excel пришёл HTML, browser POST также не вернул файл.
Причина в `fedstat_checker.run`: для полного запуска достаточно было
`checked_ok > 0`, независимо от ошибок отдельных индикаторов.

## Изменение

- Полный и точечный запуск теперь используют одинаковое условие успеха:
  хотя бы один проверенный индикатор и отсутствие неудачных скачиваний или
  пропусков без даты. Возвращаемый контракт `(downloaded_files, ok)` сохранён;
  существующий CLI преобразует `ok=False` в код выхода 2.
- Если все даты прочитаны и совпадают с сохранёнными, отсутствие новых файлов
  остаётся успешным результатом. Успешная прямая загрузка при недоступной дате
  также остаётся успехом; выдуманная дата в state не записывается.
- `pipeline.downloaders.fedstat.fetch` теперь накапливает ошибки получения даты
  и скачивания и выбрасывает `RuntimeError` с ID источников. Оркестратор уже
  перехватывает это исключение, записывает ошибку этапа `download` и не выдаёт
  результат за «не изменилось на источнике». В загрузчик передаётся прочитанная
  дата, чтобы имя файла соответствовало источнику.
- Даты успешно загруженных источников сохраняются даже при частичном сбое;
  даты неудачных загрузок не продвигаются. При сбое архивация не запускается.
  Если часть источников не изменилась, общая архивация также пропускается:
  паттерны могут охватывать несколько source IDs и иначе переместить нужные
  файлы неизменившегося источника. Старые версии в этом случае остаются локально.

## Проверка

Выполнены без сети и запуска браузера:

```text
python scripts/check_fedstat_status.py             PASS
python scripts/check_fedstat_direct_fallback.py    PASS
python scripts/check_fedstat_34118_chunks.py        PASS
python scripts/check_windows_wrappers.py          PASS
```

Новый regression script покрывает 23 сценария для полного, точечного и
pipeline-запуска: ошибку скачивания, недоступную дату, полностью неизменившиеся
данные, успешные новые загрузки, частичные обновления и direct fallback.
Проверяются итоговый статус, сохранение state, завершение драйвера, отсутствие
опасной архивации. Отдельно проверен контракт реального `_process_one`:
ошибка скачивания попадает в audit как `stage=download`, без skip и разбора
локальных файлов. Сеть и запись state подменены; файлы фикстур создаются во
временном каталоге. Проверка включена в `scripts/validate_realty_dashboard.bat`;
CRLF batch-файла сохранён.

## Границы результата

Исправлена классификация результата, а не доступность внешнего Fedstat.
Живые загрузки, `setup.bat` и полный dashboard validation не запускались;
внешние 403/HTML-ответы повторно не проверялись. Прямой fallback без даты в
pipeline-обёртку не добавлялся: для неё недоступная дата теперь явно ошибка.
Общая привязка архивируемых файлов к source ID остаётся отдельной задачей.
Production data, state и исторические логи не изменялись.
