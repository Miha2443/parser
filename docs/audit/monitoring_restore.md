## Публикация и откат

Единственный разрешённый итоговый production-файл:
`data/processed/realty_monitoring_2_0.pkl`.

Публикация завершилась успешно; `publication.json` фиксирует ровно этот
изменённый файл и **98 995** строк. Все остальные **102** защищённых файла,
включая raw, fallback, state, marts и manifest, сохранили SHA-256/размер/mtime.
Рабочий status не создавался и не подменялся. Временный ETL lock освобождён.
`outputs/audit/monitoring_restore_20260928/backup.pkl` содержит проверенную
исходную версию **70 685** строк для отката.

До подготовки: SHA-256
`92248f9699ccf73a4bafe044969abb5adf7552f5b7761cd85e7596976f1fc8e4`.
Кандидат: SHA-256
`b61d51ea47c59ea2b939481703a9273e10c8666afff6f536f18ed7c2d48467a3`.

```powershell
$env:TDM_DISABLED = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
python scripts/restore_monitoring_processed.py publish --run-dir outputs/audit/monitoring_restore_20260928
```

Публикация захватывает стандартный ETL lock без удаления чужого lock, сравнивает
SHA-256/размер/mtime всех 103 защищённых production-файлов с исходной инвентаризацией,
состав raw и хэш кандидата. Затем сохраняет `backup.pkl`, проверяет его SHA-256,
mtime и читаемость, записывает отдельный recovery-журнал `publication.json`.
На целевом разделе диска создаётся временный pickle, проверяется и атомарно
замещает один target через `os.replace`. После замены проверяются байты, полное
содержимое DataFrame и точный список изменённых production-файлов. Штатная запись
ETL/status/heartbeat и отправка уведомлений не выполняются. Python socket-сеть
заблокирована, `TDM_DISABLED=1` установлен на время команды.

При перехваченном сбое после замены автоматически возвращается проверенная
резервная копия, включая исходный mtime. Если target уже изменил другой писатель,
его версия сохраняется и ошибка остаётся явной. При жёстком завершении процесса
может остаться recovery-журнал в `backup_verified`; исходный backup уже существует.
После выяснения, что recovery-процесс завершён, контролируемый откат:

```powershell
python scripts/restore_monitoring_processed.py rollback --run-dir outputs/audit/monitoring_restore_20260928
```

Откат проверяет backup и разрешён только если текущий SHA-256 target совпадает
с этим кандидатом. Он не затирает следующую опубликованную версию. Инструмент
не удаляет старый lock автоматически; чужой или оставшийся после аварии lock
требует отдельной проверки владельца процесса. Набор разных pickle этим
однофайловым восстановлением не становится транзакционным.

## Защита новой выгрузки до публикации

`nashdom_checker._validate_monitoring_export` проверяет временный файл до
атомарной замены raw и до изменения monitoring state. Проверка ZIP-сигнатуры
дополнена реальным открытием XLSX, обязательными листами «Реестр РВ» / «Реестр
ОКС» и необходимыми колонками, непустыми таблицами и числовыми площадями,
неотрицательностью первичных площадей, допустимыми годами РВ и отсутствием
бесконечных/NaN метрик. Формулы заголовков Google Sheets проверяются по
**cached values**, которые фактически читает pandas, а не по тексту формулы.
Затем общий `DataAccess` читает явный временный источник: нужны непустые оба
реестра, сохранённые первичные РВ и конечные производные площади.

Повтор в тот же день дополнительно сравнивает реальные байты target с ответом
и тоже проходит семантическую проверку. Состояние с совпавшим SHA само по себе
не подтверждает пригодность файла. При ошибке возвращается `([], False)`;
последний корректный raw, его mtime и monitoring state остаются прежними.
Существующий общий `run()` может повторно сериализовать неизменённый state —
новая проверка не записывает ложные сведения об успешной загрузке.

`scripts/check_monitoring_download_guard.py`: **8 PASS**, включая реальные
XLSX, равные компоненты, ноль, NBSP/пробел/запятую, неверные/пустые схемы,
inf/NaN/отрицательные площади, обход через same-day state, повреждённый target,
формулы заголовков с кэшем и без кэша. HTTP подменён локальными байтами, socket
сеть запрещена. Прежний `check_nashdom_contract.py` теперь использует настоящий
XLSX вместо фиктивных `PK`-байтов и тоже проходит. Сохранённый реальный Google
export 17 июля проверен без записи и принят. Другие download flows не менялись.
Эти проверки не доказывают полноту источника по всем объектам или его свежесть.
